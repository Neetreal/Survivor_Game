# Какие файлы арта ждёт игра

Всё, что лежит в `art/`, при загрузке на GitHub не прошло. Игра от этого **не ломается**:
в `player.gd` / `enemy.gd` / `fx_visual.gd` есть фолбэк — если PNG нет, `Body` скрывается
и показывается старый цветной `Polygon2D`. Но выглядит это как кружочки, так что арт нужен.

Ниже — точный список имён, которые код ищет в рантайме. Пути собираются по шаблонам
(`hero_%s.png`, `enemy_%s.png`, `%s.png`), поэтому в сценах этих ссылок не видно — список
собран по местам вызова `load()` и `FxVisual.use_sprite()`.

## Герои — 5 штук × 3 кадра

Папка `art/sprites/`, высота ~40 px, PNG с прозрачностью, вид сверху-3/4.

| id | базовый | шаг 1 | шаг 2 |
|---|---|---|---|
| `archer` Лучник | `hero_archer.png` | `hero_archer_walk1.png` | `hero_archer_walk2.png` |
| `knight` Рыцарь | `hero_knight.png` | `hero_knight_walk1.png` | `hero_knight_walk2.png` |
| `storm` Грозовой маг | `hero_storm.png` | `hero_storm_walk1.png` | `hero_storm_walk2.png` |
| `druid` Друид | `hero_druid.png` | `hero_druid_walk1.png` | `hero_druid_walk2.png` |
| `fire` Огненный маг | `hero_fire.png` | `hero_fire_walk1.png` | `hero_fire_walk2.png` |

Кадры шага обязаны быть на **общем холсте** (центр по X, привязка по низу) — иначе
персонаж дёргается. Именно для этого в `tools/make_sprites.py` есть `--common-canvas`.

## Враги — 11 базовых спрайтов

Файлы `enemy_<тип>.png`, высота 40 px (босс 46 px). Мини-боссы (`mb_slime`, `mb_bat`,
`mb_brute`, `mb_spitter`) отдельных файлов **не требуют** — код обрезает префикс
`mb_` и берёт спрайт обычного типа, увеличивая его масштабом.

`enemy_slime.png`, `enemy_bat.png`, `enemy_brute.png`, `enemy_spitter.png`,
`enemy_splitter.png`, `enemy_elite.png`, `enemy_boss.png`, `enemy_shieldbearer.png`,
`enemy_bomber.png`, `enemy_healer.png`, `enemy_gem_eater.png`

Покадровый шаг (`enemy_<тип>_walk1.png` + `_walk2.png`) был у четырёх:
`elite`, `shieldbearer`, `healer`, `boss`. Остальные анимируются процедурно
(покачивание, сквош) — для них кадры не нужны.

## Как загрузить, если GitHub ругается на много файлов

Веб-интерфейс GitHub плохо переживает загрузку сотни мелких PNG: вкладка отваливается
по таймауту («сайт не отвечает»). Обход — **загрузить один архив вместо сотни файлов**:

1. на компьютере заархивировать папку `art` в `art.zip` (`zip -r art.zip art/`);
2. на GitHub: **Add file → Upload files** → перетащить один `art.zip` → **Commit changes**;
3. написать в чат — архив распакуют, разложат по `art/sprites/`, `art/raw/`, `art/preview/`
   и уберут сам zip из репозитория.

Ограничение веб-загрузки — 25 МБ на файл; исходники спрайтов весят на порядок меньше.

Если архива нет под рукой (он остался только в старом чате) — можно заново нарезать
арт генератором: `tools/make_sprites.py` ждёт исходники на пурпурном фоне `#FF00FF`
в `art/raw/`, вырезает хромакей и складывает готовые PNG в `art/sprites/`.
